# Text

Text
To understand why modalities other than text need to be encoded differently, let’s
start by exploring the main components of the LLM.
A common approach to LLM architecture design is to use a tokenizer to split a given
text up into pieces (also tokens), where each token is embedded before being passed
to a decoder-only LLM (Figure 9-7).

The resulting token embeddings are the LLM’s main component to process the input
information. Aside from the tokens and token IDs, these numeric representations can
be seen as the main input of the LLM. This is also one of the primary places we add
other modalities. By encoding other modalities into embeddings, the LLM now has
the same type of information to process (Figure 9-9).

This view can help us understand this encoding process a bit more. The tokenizer,
together with the embedding layer (token embeddings), can be seen as the text
encoder (Figure 9-10).

embeddings generated by one modality (e.g., images) might be completely different
from another modality (e.g., audio), as shown in Figure 9-11.

value distributions. Before we explore such projection techniques, let’s first look into
methods of encoding different modalities.
